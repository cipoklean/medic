## 4. The patient agent
- A small research agent that answers a question using 3 tools: `web_search(query)`, `fetch_page(url)`, `calculator(expression)`.
- **Tools read from `fixtures/`** (map query/url -> stored result). Unknown query returns a clear "no results" — never hits the network in demo mode. (A `--live` flag may exist but is off by default.)
- Loop: LLM with tool-calling, up to `max_steps` from `medic.yaml`. Records every step.
- Everything it's allowed to change lives in `medic.yaml`:
yaml
system_prompt: |
  ...
tools:
  web_search: {description: "..."}
  fetch_page: {description: "..."}
  calculator: {description: "..."}
max_steps: 8
retry_on_parse_error: false
- **Dual tracing:** every span goes to neatlogs AND to `runs/<run_id>.json` (our own recorder: span name, kind, input, output, error, tokens, timings). Medic can run on either source.

## 5. The bugs (presets) and their hard checks
Build in this order. Bug 4 is hardest: build its check first, and drop it if time runs short.

| # | Bug preset (injected into medic.yaml / tool behavior) | Hard check (no LLM) |
|---|---|---|
| 1 | **Wrong arguments:** vague `calculator` description → model passes prose instead of an expression | Every tool call validates against its JSON schema AND final answer equals the known value in `tasks/*.yaml` |
| 2 | **Malformed JSON:** a fixture tool returns slightly broken JSON and `retry_on_parse_error: false` | Run completes with no unhandled parse exception and answer is correct |
| 3 | **Infinite loop:** prompt lacks a stop rule, `max_steps` high → agent keeps searching | Finishes in ≤ N steps (N in task file) with a final answer |
| 4 | **Hallucinated citations:** prompt invites "cite sources" without requiring fetched evidence | Every URL cited in the answer appears in a `fetch_page` result from that run |

Each task in `train.yaml`/`heldout.yaml` has: `id, bug, question, expected_answer (or check params), max_steps_allowed`.

## 6. Medic
1. **trace_source.py** — `load_trace(run_id)`: try neatlogs read API (find the exact read endpoint and auth in https://docs.neatlogs.com/api-reference; `GET /api/traces/v3/:traceId` exists); on any failure fall back to `runs/<run_id>.json`. Normalize both into one `Trace` pydantic model (list of spans with parent ids).
2. **diagnose.py** — sends a compact span tree (truncate long outputs) + the failing check result to the LLM. Returns JSON validated by pydantic:
   `{failing_span_id, failure_type: wrong_args|parse_error|loop|hallucinated_citation|other, evidence, root_cause, confidence}`.
3. **surgeon.py** — given diagnosis + current `medic.yaml`, returns a structured patch: `{field: system_prompt|tools.<name>.description|max_steps|retry_on_parse_error, new_value, rationale}`. Apply it to a copy, show a unified diff, write it only if verification passes (or on `--apply`).
4. **verify.py** — rerun the train task, then all held-out tasks for that bug. Run hard checks. Collect per-run metrics: pass/fail, steps, prompt+completion tokens, est. cost, latency.
5. **loop.py** — up to 3 attempts. Each failed attempt feeds the new trace + failed check back to diagnose. Stop on first full pass (train + heldout).
6. All LLM calls by Medic are also traced to neatlogs under `workflow_name="medic"`.
